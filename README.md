# E-3 Mini NPU Simulator

Python 기본 문법과 표준 라이브러리를 사용하여 MAC(Multiply-Accumulate) 연산을 직접 구현하고, 입력 패턴과 필터의 유사도를 비교하는 Mini NPU 시뮬레이터입니다.

3×3 사용자 입력 모드와 `data.json` 분석 모드를 지원하며, 5×5 / 13×13 / 25×25 패턴에 대한 일괄 판정과 크기별 연산 시간 측정을 수행합니다.

## 주요 기능

- 3×3 필터 A/B 및 패턴 콘솔 입력
- 행/열 개수 및 숫자 입력 검증
- 반복문을 이용한 MAC 연산 직접 구현
- `epsilon = 1e-9` 기반 동점 판정
- `data.json`의 5×5 / 13×13 / 25×25 필터와 패턴 분석
- `+`, `cross`, `x` 라벨을 `Cross`, `X`로 정규화
- 필터와 패턴 크기 검증
- 케이스별 `Cross / X / UNDECIDED` 판정
- `expected` 값과 비교하여 `PASS / FAIL` 출력
- 크기별 MAC 연산 10회 반복 후 평균 시간 측정
- 전체 테스트 수 / 통과 수 / 실패 수 요약

## 실행 방법

Python 3.8 이상이 필요하며 NumPy, pandas 등의 외부 라이브러리는 사용하지 않습니다.

프로젝트 디렉토리에서 다음 명령어를 실행합니다.

```bash
python3 main.py
```

실행하면 다음 두 가지 모드 중 하나를 선택할 수 있습니다.

```text
=== Mini NPU Simulator ===

[모드 선택]
1. 사용자 입력 (3x3)
2. data.json 분석
선택:
```

### 1. 사용자 입력 모드

`1`을 선택한 뒤 필터 A, 필터 B, 입력 패턴을 각각 3줄씩 입력합니다.

예시:

```text
0 1 0
1 1 1
0 1 0
```

각 줄은 공백으로 구분된 숫자 3개로 구성되어야 합니다. 올바르지 않은 입력이 들어오면 안내 메시지를 출력하고 해당 행을 다시 입력받습니다.

### 2. data.json 분석 모드

`2`를 선택하면 프로젝트 루트의 `data.json`을 읽고 다음 순서로 분석합니다.

1. 5×5 / 13×13 / 25×25 필터 로드
2. 패턴 키에서 크기 `N` 추출
3. 패턴과 필터 크기 검증
4. 라벨 정규화
5. Cross/X 필터에 대한 MAC 점수 계산
6. Cross / X / UNDECIDED 판정
7. `expected`와 비교하여 PASS / FAIL 출력
8. 크기별 성능 분석
9. 전체 결과 요약

## 구현 요약

### MAC 연산

MAC 연산은 외부 라이브러리를 사용하지 않고 이중 반복문으로 직접 구현했습니다.

각 위치의 입력 패턴 값과 필터 값을 곱한 뒤 모든 값을 누적하여 최종 점수를 구합니다.

```text
score = Σ(pattern[i][j] × filter[i][j])
```

### 라벨 정규화

외부 데이터의 표현을 프로그램 내부에서는 두 개의 표준 라벨로 통일합니다.

```text
+       → Cross
cross   → Cross
x       → X
```

이 과정을 통해 필터 키와 `expected` 값의 표현 방식이 달라도 동일한 기준으로 비교할 수 있습니다.

### 부동소수점 비교 정책

실수 계산에서 매우 작은 오차가 발생할 수 있으므로 두 점수를 단순히 `==`로 비교하지 않습니다.

```text
epsilon = 1e-9
```

두 점수의 차이가 `epsilon`보다 작으면 `UNDECIDED`로 처리합니다.

```text
abs(score_a - score_b) < epsilon
```

## 결과 리포트

이번 구현에서는 5×5, 13×13, 25×25 크기에 대해 Cross와 X 패턴을 각각 분석할 수 있도록 구성했습니다.

프로그램은 각 패턴 키에서 크기를 추출하고 같은 크기의 필터를 자동으로 선택합니다.

`data.json`의 `+`와 `x`, 필터 키의 `cross`와 `x`는 프로그램 내부에서 각각 `Cross`, `X`로 정규화됩니다.

따라서 데이터에 사용된 외부 라벨 표현과 내부 비교 라벨의 차이 때문에 발생할 수 있는 판정 오류를 방지할 수 있습니다.

MAC 점수 비교에는 `epsilon = 1e-9`를 사용했습니다.

이를 통해 부동소수점 표현 차이처럼 실제 의미상 동일한 점수가 아주 작은 수치 차이로 서로 다른 값으로 판단되는 문제를 방지했습니다.

필터와 패턴의 크기도 MAC 연산 전에 확인하여 잘못된 데이터가 들어왔을 때 프로그램 전체가 비정상 종료되지 않도록 구성했습니다.

정상 데이터에서는 각 Cross/X 패턴이 대응하는 필터와 가장 높은 MAC 점수를 가지므로 예상 라벨과 같은 결과를 얻을 수 있습니다.

실패 케이스가 발생하는 경우에는 단순히 FAIL만 출력하는 것이 아니라 케이스 식별자와 실패 원인을 함께 기록하도록 구현했습니다.

이 구조를 통해 데이터/스키마 문제, 판정 로직 문제, 수치 비교 문제를 구분하여 확인할 수 있습니다.

## 성능 분석 및 시간 복잡도

N×N 패턴과 필터의 MAC 연산에서는 모든 위치를 한 번씩 확인합니다.

따라서 한 번의 MAC 연산에서 수행되는 곱셈 횟수는 `N²`입니다.

| 크기 | MAC 연산 횟수 |
|---|---:|
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

프로그램에서는 각 크기의 MAC 연산을 최소 10회 반복한 뒤 평균 시간을 ms 단위로 출력합니다.

입력 크기 `N`이 커질수록 처리해야 하는 원소 수가 `N²`에 비례하여 증가하므로 MAC 연산의 시간 복잡도는 **O(N²)**입니다.

실제 평균 실행 시간은 CPU 상태와 실행 환경에 따라 매번 조금씩 달라질 수 있으므로, 특정 시간값 자체보다는 크기가 증가하면서 연산 횟수가 증가하는 관계를 중심으로 분석했습니다.
