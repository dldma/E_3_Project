# 04. 성능 분석 및 결과 요약

## 목적

패턴 크기가 커질수록 MAC 연산에 필요한 연산 횟수와 실행 시간이 어떻게 변화하는지 확인합니다.

## 측정 방법

성능 측정 시 사용자 입력, 콘솔 출력, JSON 파일 읽기 시간은 제외하고 MAC 연산 함수 호출 구간을 중심으로 측정합니다.

각 크기에 대해 MAC 연산을 10회 반복한 뒤 평균 시간을 ms 단위로 계산합니다.

```text
평균 시간 = 10회 MAC 연산 시간의 합 / 10
```

## 연산 횟수

N×N 배열의 모든 위치를 한 번씩 처리하므로 MAC 연산 횟수는 `N²`입니다.

| 크기 | 연산 횟수 N² |
|---|---:|
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

따라서 입력 크기 N에 대한 시간 복잡도는 다음과 같습니다.

```text
O(N²)
```

3×3에서 25×25로 증가하면 처리하는 위치의 수는 9개에서 625개로 증가합니다. 실제 시간은 실행 시점의 CPU 상태에 따라 달라질 수 있지만, 입력 크기가 커질수록 반복문의 실행 횟수가 크게 증가하는 구조를 확인할 수 있습니다.

## 결과 요약

현재 `data.json`은 5×5, 13×13, 25×25에 대해 Cross와 X 테스트를 각각 포함하도록 구성되어 있습니다.

따라서 정상 실행 시 총 6개의 케이스를 순차적으로 판정합니다.

각 케이스는 라벨 정규화 후 Cross/X MAC 점수를 비교하고, `expected`와 같은 경우 PASS로 기록합니다.

실패 케이스가 발생하는 경우 케이스 식별자와 사유를 별도로 기록하여 데이터/스키마 문제, 로직 문제, 수치 비교 문제를 구분할 수 있도록 했습니다.
